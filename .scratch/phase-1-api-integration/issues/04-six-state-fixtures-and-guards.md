# 04: 六态夹具与铁律 2 红线守卫

**What to build:** 让六态（`0` / `—` / 暂不可用 / 暂无内容 / 样本不足 / 待确认）每一态都有可触发的样例和自动断言，并把「字段级 `null` 绝不落成 `0`」这条铁律变成**会失败的测试**。演示数据是自洽生成的、永远不缺字段，所以这条铁律在当前代码里从来没有被真正执行过一次；真实数据一接上，大量 AI 派生字段会是 `null`，那一刻才发现渲染成了 `0`，就是在向产品团队撒谎。这张工单是整份 spec 的硬要求，后面每一张页面工单都靠它兜底。

**Blocked by:** 01, 02

**Status:** ready-for-agent

## 验收标准

- [ ] 演示 provider 支持按需产出六态样本，用**确定性**方式触发，不靠随机
- [ ] **反向断言**：确实有数据且为零的字段仍渲染 `0`。防止「一律不显示 0」矫枉过正把真零也抹掉——`0` 是「已取得数据且确实为零」的专用值
- [ ] **红线断言**：对每个可为 `null` 的字段构造 `null` 响应，断言渲染结果**既不是 `0` 也不是空串**。这是铁律 2 的唯一自动化护栏
- [ ] 三套缺失文案分别断言且**不可互换**：
      状态图例／短徽章 → 「暂不可用」「暂无内容」（PRD §3.6 逐字）；
      数值位与环比位 → 「数据暂不可用」（PRD §3.1、§5 `delta()` 契约）；
      空态 → 「暂无相关内容」（PRD §4.1 逐字）
- [ ] `—` 态断言：结构性不适用的字段渲染 `—`
- [ ] 样本不足断言：有效产品态度评论 < `LOW_SAMPLE`(10) 时不输出倾向结论
- [ ] 待确认断言：标注 `confidence < lowConfidence`(0.7) 时显示「待确认」
- [ ] 后端端点测试模板成型，四类各一例供后续端点照抄：**形状**（200 + 信封 + 形状同 PRD §5）、**六态**、**确定性**（连调两次逐字节相同）、**口径逐字**（热度／去重／基准区间／环比的说明文字对齐 PRD 第 3 章）
- [ ] 三条静态 grep 守卫跑在测试套件里：
      ① 屏幕代码中不得出现 `R.hash`/`R.rnd`/`R.pick`/`R.pickN`/`R.addDays`（ADR-0004）；
      ② 门面与垫片层不得出现 `?? 0`/`|| 0`/`|| []`（ADR-0005）；
      ③ 前后端业务逻辑不得出现 `new Date()`/`datetime.now()`，展示层格式化除外（ADR-0012）
- [ ] 守卫 ① 当前**应当失败**：官号动态页在用 `R.hash`、KOL 详情页在用 `R.addDays`。本单只要求守卫建起来并如实报红，修复分别在 05 与 07
