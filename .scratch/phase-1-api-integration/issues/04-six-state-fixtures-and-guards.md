# 04: 六态夹具与铁律 2 红线守卫

**What to build:** 让六态（`0` / `—` / 暂不可用 / 暂无内容 / 样本不足 / 待确认）每一态都有可触发的样例和自动断言，并把「字段级 `null` 绝不落成 `0`」这条铁律变成**会失败的测试**。演示数据是自洽生成的、永远不缺字段，所以这条铁律在当前代码里从来没有被真正执行过一次；真实数据一接上，大量 AI 派生字段会是 `null`，那一刻才发现渲染成了 `0`，就是在向产品团队撒谎。这张工单是整份 spec 的硬要求，后面每一张页面工单都靠它兜底。

**Blocked by:** 01, 02

**Status:** done

## 验收标准

- [x] 演示 provider 支持按需产出六态样本，用**确定性**方式触发，不靠随机
- [x] **反向断言**：确实有数据且为零的字段仍渲染 `0`。防止「一律不显示 0」矫枉过正把真零也抹掉——`0` 是「已取得数据且确实为零」的专用值
- [x] **红线断言**：对每个可为 `null` 的字段构造 `null` 响应，断言渲染结果**既不是 `0` 也不是空串**。这是铁律 2 的唯一自动化护栏
- [x] 三套缺失文案分别断言且**不可互换**：
      状态图例／短徽章 → 「暂不可用」「暂无内容」（PRD §3.6 逐字）；
      数值位与环比位 → 「数据暂不可用」（PRD §3.1、§5 `delta()` 契约）；
      空态 → 「暂无相关内容」（PRD §4.1 逐字）
- [x] `—` 态断言：结构性不适用的字段渲染 `—`
- [x] 样本不足断言：有效产品态度评论 < `LOW_SAMPLE`(10) 时不输出倾向结论
- [x] 待确认断言：标注 `confidence < lowConfidence`(0.7) 时显示「待确认」
- [x] 后端端点测试模板成型，四类各一例供后续端点照抄：**形状**（200 + 信封 + 形状同 PRD §5）、**六态**、**确定性**（连调两次逐字节相同）、**口径逐字**（热度／去重／基准区间／环比的说明文字对齐 PRD 第 3 章）
- [x] 三条静态 grep 守卫跑在测试套件里：
      ① 屏幕代码中不得出现 `R.hash`/`R.rnd`/`R.pick`/`R.pickN`/`R.addDays`（ADR-0004）；
      ② 门面与垫片层不得出现 `?? 0`/`|| 0`/`|| []`（ADR-0005）；
      ③ 前后端业务逻辑不得出现 `new Date()`/`datetime.now()`，展示层格式化除外（ADR-0012）
- [x] 守卫 ① 当前**应当失败**：官号动态页在用 `R.hash`、KOL 详情页在用 `R.addDays`。本单只要求守卫建起来并如实报红，修复分别在 05 与 07

## Comments

**六态样本用「场景叠加」而不是另一份完整 fixture。** `DEMO_SCENARIO=sixstate` 时，
provider 先查 `fixtures/sixstate/`，再回落 `fixtures/demo/`，**逐键**回落而不是整目录二选一。
否则要造一条 null 就得把整份演示数据复制一遍，复制出来的那份还会慢慢和主份漂开，
半年后没人知道两边差异是有意还是过期。`test_scenario_falls_back_to_demo_for_untouched_keys`
和 `test_default_scenario_is_untouched_demo_data` 一正一反钉住这个行为。

**六个样本每条只演一态，全部写死**（`fixtures/make_sixstate.py`）：
`sixstate-zero` 真零 · `sixstate-null` 计数字段 null · `sixstate-pending` conf 0.42 ·
`sixstate-confident` conf 0.96 · `sixstate-nosummary` 图片帖无摘要 · `sixstate-nomention`
区间内未提及 ETF。一条演多态的话，断言失败时说不清是哪一态坏了。

**两头都测。** 后端 `tests/test_six_states.py` 管「有没有说实话」（null 原样上线、
空集是 empty 不是 unavailable）；前端 `scripts/six-state.mjs` 管「页面有没有照实说」
（起一套 8018 + 5175 的独立站点，用 Playwright 读实际渲染文字）。
只测后端挡不住渲染层一句 `value || 0`，而那正是最容易发生、后果最坏的那种错。

**前端断言必须限定在一张卡片之内。** 整页 `includes('赞 0')` 毫无意义——页面上总有别的卡
真的就是 0。第一版用固定长度窗口，溢到下一张卡上，报了 3 条假红（渲染其实是对的）。
改成按「原帖 ↗」切卡、用该卡独有的摘要句认卡。

**守卫排在 `npm test` 最后，且不设豁免名单。** 守卫 ① 现在如实报两处红
（`OfficialActivity.jsx:177 R.hash`、`KolDetail.jsx:159 R.addDays`），分别由 05 和 07 拔掉。
豁免名单一旦开了口子就不会有人再删；排到最后则保证前面的六态红线和五页逐字比对
照跑照报，不被这条已知的红挡住。

**守卫要先挖注释再 grep。** 三条守卫的说明文字里逐字引用了它们自己禁止的写法，
不挖的话守卫第一个就把自己告了，然后大家学到的是「这守卫老是误报」，接着就把它关了。
`stripComments()` 用等长空格替换，行号列号都不动。
