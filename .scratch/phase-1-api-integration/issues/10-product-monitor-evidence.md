## Comments

**验证**：后端 303 个测试（新增 28：`test_evidence.py`）、六态 45 条、五页 9 次逐字比对（`/product` 三态）、4 条静态守卫、`npm run build` 干净。

**唯一一处判给 PRD、没跟设计源走的地方：`dominantAttitude` 为 `null` 时那一格。** 设计源渲染「样本不足」，PRD §3.6 六态表、§5 表 P8 和本期 spec 都说字段级 `null` 一律是「暂不可用」。两句话在这里不是同义词——「样本不足」是我们**查过了、看过了那几条、决定不下结论**；「暂不可用」是这一格**没有值**。而 `mentionCommentCount` 就在同一行左边写着 `2`，读的人自己能看出样本少；把这格也说成「样本不足」，等于让这一行两次说同一件事，反而遮住了「这里本该有个态度标签」。措辞按 PRD 改，徽章配色仍用设计源的灰。这处偏差在 `screen-diff.mjs` 的 WHITELIST 里记了第二条（带出处），逐字比对时作为**已知豁免**显示出来而不是消失——实测只在「产品相关 KOL 全部展开」那一视图里落 2 处，`3033·d7` 九位 KOL 里只有第 9 位（2 条提及）处在这个状态。

**证据侧栏的 `ctxKey` 是「哪一个结论」的地址，不是一个筛选条件。** 页面上五种入口各自生成一种 id：舆情总结 `sum`、正负面主题 `<code>-pos|neg-<i>`、观点主题 `<code>-tp-<i>`、竞品 `<竞品代码><极性>`、阶段 `stage-<n>-<起始日>`。它们不是枚举，是**从别的端点的返回值里拼出来的**——所以后端不能校验它长什么样，只能校验它有没有对应的证据条目，取不到就是 404 而不是空数组。这条线最容易断的地方是竞品：那个 id 里带的是**竞品的代码**，证据也存在竞品名下，前端因此还要传一个 `evidenceCode`。`test_competitor_evidence_lives_under_the_competitor_code` 钉的就是这个，写错了会安静地退化成「看自家产品的证据」。

**四个参数各配了一条「没被静默忽略」的断言**，因为这条链断在任何一节都不报错，只是给你一份看起来很合理的数据。`n`：改 `n` 必须换来**恰好** `n` 条、且 id 集合正好是前 `n` 个（不是「长度对了」）。`ctx`：三个真实上下文的摘要库互不相交（验过）。`range`（藏在 `ctx` 前缀里）：换区间必须换内容。`polarity`：fixture 只存每个上下文**实际用到**的那一个极性，所以 `d7|sum` 配 `positive` 是 404——这个 404 本身就是「极性参与了寻址」的证据。

**`n` 的钳位从前端搬到了后端。** 原来屏里写着 `Math.max(1, Math.min(12, p.count || 6))`，那是口径（铁律 1），现在只在 `core/evidence.py` 一份，屏里原样转发 `p.count`、不传就不发 `n=`。搬的时候踩了一次：我先按「合理」的读法写了断言，`n=0` 应该是 1 条吧？测试红了才回去看设计源——`count || 6` 把 `0` 读成「没传」，所以 `n=0` 是 6 条，`n=-3` 才是 1 条。这不是代码 bug 是测试 bug，但值得记下来：「0 表示不限」和「0 表示一条都不要」都是很自然的误读，而这一格的真相是第三种。

**fixture 存的是 `{items, orders}`，不是一个排好序的列表。** 设计源的比较函数 `a.publishedAt < b.publishedAt ? 1 : -1` 在两条时间相同时返回 −1，于是并列项的先后取决于 V8 的排序实现，Python 的稳定排序复现不出来。所以生成脚本把 `n=1..12` 各自的次序全都跑一遍存下来，`demo.py` 只按下标取、不排序。这不是为了性能，是为了让「逐字一致」这四个字在有并列时间戳的那几条上仍然成立。

**六态样本自己撞了自己一次。** 造「提及 < 3 条」那行时我把 KOL 名起成「六态样本 · 样本不足」，而同一条断言 reject 的正是「样本不足」——样本带着要拒绝的字，红灯报的是自己。顺带发现同一行 `mentionCommentCount=2` 却留着供体的 13 条证据，页面上会出现「提及 2 条」配「证据 13 条 →」。两处都改了：名字里不再出现方向词与状态词，三个计数字段在 fixture 里也保持契约里的同一个数。

**证据侧栏的六态断言需要「先点开再看」，为此 `six-state.mjs` 加了 `open` 钩子**（`screen-diff.mjs` 的 `views` 已有先例）。等待的对象必须是**只有点开后才有**的字，不能是定时等待——09 那次假绿就是这么来的，这已经是第三次遇到同一类错误。空态那页等空态那句话本身，有证据那页等「展开单帖详情」，两者恰好互斥。另外抽屉里的对照卡排第一是有原因的：断言按「展开单帖详情」把整页切成一张张卡，**第一张卡那一段还粘着它前面的整个页面**，页面别处的「暂不可用」会让反向断言当场撞上。放一张不被断言的卡在最前面，后面三张就各自干净地占一段。

**长短两套文案在同一张证据卡上并存**（PRD §3.6 与 §3.1／§5 `delta()` 契约，两套不可互换）：作者名取不到 → 数值位长文案「数据暂不可用」，隔壁评论／互动计数取不到 → 短徽章「暂不可用」。把它们统一成一句是很自然的「顺手整理」，所以专门写了一条断言钉在同一张卡上——同时验两套还在，也验它们没被合并。

**没做的事**：阶段面板的证据入口（`stage-<n>-<起始日>`）fixture 里已经有了，但 `test_every_panel_on_the_product_page_has_an_entry` 还没把它列进去——阶段本身在 11，那条断言随 11 一起补。`/product` 整页 diff 目前是 3/3 绿，但页面上的 K 线与阶段还读着设计源镜像，真正的「整页脱镜像」也在 11。
