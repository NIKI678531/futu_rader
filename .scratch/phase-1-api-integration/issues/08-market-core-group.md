## Comments

**验收结果.** 后端 245 passed（其中 `backend/tests/test_market.py` 新增 61 条）；前端 `npm test` 全绿：六态 36 条、五页 diff 逐字一致（白名单豁免 2）、四条静态守卫；`npm run build` 干净。

**`delta` 的形状比工单写的多两个字段，是有意的。** 工单写 `{abs, pct, dir}`，实际下发 `{text, short, abs, pct, dir}`。缺失文案本身就是口径（铁律 2 规定了「数据暂不可用」与「暂不可用」两套不可互换的文案），让前端按 `abs == null` 自己拼文案，等于把口径分成两份实现。同理，"输入缺失时整体为 `null`" 改成**形状恒在、`abs === null` 表示不可用**——整体 `null` 会让前端在渲染处先判空再决定文案，那正是铁律 1 要消灭的东西。
配套的一个坑写进了测试：`pct === null` **不**代表不可用（基准期为 0 时 `abs` 有值而 `pct` 无从谈起），判据只有 `abs === null`（`test_zero_base_is_new_not_unavailable`）。

**新增守卫④「屏幕代码里不得调用口径公式」**（`R.delta` / `R.heatOf`）。加之前先 `git show HEAD:` 查过两个屏幕，各有一处真实的 `R.delta` 调用——不是空守卫。环比现在由后端内嵌在它所描述的那个数旁边下发。

**`numRaw()`：与 `num()` 同一道 null 关口，不打千分位。** 设计源在悬浮卡、候选列表这类窄列里逐字用的是 `String(v)`，而桶值会过千（d30 峰值 6057），直接套 `num()` 会引入真实文本差异。宁可多一个函数，也不为了省一个函数放松 null 关口。

**`filtered()` 与 `pqHits` 改成遍历 `pool().list`，不再遍历 `R.ORDER`。** 语义等价（池本身就是 `ORDER.map(observe)`），但同时解决了两件事：一是六态场景的池是手工裁到 8 只的，按 120 只的 ORDER 去取会取出 `undefined`；二是它直白地说出「可见集来自池」（铁律 3）。

**screen-diff 有了第一条白名单：`/sector` 的「其中需合规关注」。** 设计源那句 `|| 0` 把一只没做过合规扫描的自家产品（3153）当 0 条加了进去，于是它言之凿凿地写「27 条」。移植版渲染「数据暂不可用」——这是两边唯一一处有意的文本差异，也是唯一一处移植版比设计源更准。白名单里写了出处。

**色阶标尺这条的实情，别读成比实际更强。** 后端下发了 `pool.globalMax`，但页面上真正在用的两把标尺是：卡片底色＝**全池**讨论热度排名分段（`P.list` 全量排序，与可见集无关），时段热力条＝**该产品自己**的区间峰值归一（设计源逐字如此）。两者的输入都与筛选无关，所以标尺不随筛选变；`globalMax` 目前无人读取，是为后续留的。这条算过，但它成立的理由是「输入是全池」，不是「用了 globalMax」。

**排名稳定性是在浏览器里点出来的**，脚本留在 `.scratch/phase-1-api-integration/rank-stability.mjs`（一次性，不进 `npm test`）：3133，全市场第 25 名，依次切板块／新品／抽屉搜索／页顶快捷搜索共 10 次，`第 25 ／ 120 只` 一次没动。
挑第 25 名而不是第 1 名是关键——第 1 名在几乎任何筛选下都还是第 1 名，用它测等于没测。切到 A股 时可见集从 120 只掉到 22 只，如果排名按可见集重算，这个数会掉到个位数。
第一版脚本按文字找 chip，点到了页头身份卡上那个同名的死标签「A股」，什么都没发生却一路绿——定位器现在锁在抽屉的筛选栏内部。
