## Comments

**屏幕上还剩 6 处 `R.*`，全部后端供数。** `officialPosts` / `buildRange` / `etfMentionsFor`
是契约函数，`OFFICIAL` / `MASTER` / `ETF_MENTION_RULE` 是 `/meta`。镜像上的成员一个都不读了。

**`R.hash` 的去处：主页地址是账号的属性，不是页面能算出来的东西。** 设计源里官号主页链接是
`'https://www.futunn.com/user/' + (10000000 + hash(全称) % 80000000)` —— 演示数据生成器
泄漏进了屏幕代码（ADR-0004）。搬进后端主数据（`fixtures/generate.mjs` 里用设计源自己的
`hash` 算一次，值不变），屏幕改读 `o.url`。接真实库后这个字段来自账号表，屏幕不用改。

**由此发现比对脚本有个洞：它只比文本节点，`href` 根本没进比对。** 本条验收要求的正是
「地址不变」，而当时那个全绿的 diff 对地址一无所知。已扩展 `screen-diff.mjs`：除文本外
再比**站外链接序列**（用 `getAttribute` 而不是 `.href`，后者会按端口补全，站内链接必然假红；
站内导航本来就该不一样 —— DcLink 会把 `.dc.html` 改写成路由）。官号页 50 条站外链接
（20 个主页 + 30 个原帖）逐字一致，这才算真的验过了。

**「后端连不上」补成了 six-state 的第 ⑧ 条断言。** 它是前七条的对照组：六态说的是
「这个字段怎么了」，前提是接口答了；接口没答的时候一个数字都不能信，只能整屏说清楚。
测法是在浏览器层 abort 掉 `**/api/v1/**`，不停后端 —— 停后端会连带影响别的断言。
断言除错误条之外页面上不该再有 `原帖 ↗`、表头、`数据暂不可用`：半屏真数据半屏错误提示
比整屏报错更糟。判定时要先把错误条自己的文本减掉 —— 它的文案里就引用了「数据暂不可用」
（它正是在说「这不是数据暂不可用」），拿整页文本判会被自己的话绊倒。为此给错误条加了
`data-screen-error`（属性不产生文本，不影响逐字比对）。

**顺手修了 `screen-diff.mjs` 的孤儿进程问题**（与 04 修 six-state 的是同一个 bug）：
Windows 上 `shell:true` 起的是一层 `npm.cmd`，`child.kill()` 杀不到真正占端口的 node，
下次跑 diff 会连到一个跑着旧代码的站点 —— 一种会让你相信错误结论的失效。
