# 账号板块重构：需求确认与改版设计方案

> 整理自 2026-09-06 与客户的口头对接记录。
> 口语转写修正：原记录中的「QL」均指 **KOL**，「关号」均指 **官号**。
> 适用范围：账号板块三个页面 —— `kol-activity.dc.html`（KOL 影响力）、`kol-detail.dc.html`（KOL 详情）、`official-activity.dc.html`（官号动态）。

---

## 一、背景：为什么要改

**数据采集方式的硬约束**（与 `_verify` 实测核验结论一致）：

| 数据 | 可得性 | 依据 |
|---|---|---|
| KOL / 官号在跟踪标的下的帖子全文、发布时间 | ✅ 可得 | 采集按 ETF 标的驱动，帖子本体完整 |
| 帖子的赞数、评论数（计数）、转发数、浏览数 | ✅ 可得（发布后约 24h 的值） | `like_count` / `comment_count` / `share_count` |
| 帖子评论区的**逐条评论内容** | ❌ 不可得 | 仅第一页，重点 KOL 帖 66.8% 被截断，近 30 天全部重点 KOL 仅 425 条评论落库 |

因此：**一切依赖"评论区内容"的分析（好差评、每小时评论分布、评论摘录、评论人分层）都无法成立，全部下线；分析对象转向"帖子本身"——AI 摘要、类型识别、自家/竞品统计。**

> 注：帖子的**评论数（一个数字）**是平台计数字段，依然可得。建议作为普通互动指标（赞/评/转）保留展示——只是不再有任何"评论内容"层面的分析。此点建议与客户确认（见 2.4-C3）。

### 2.2 新增项（客户明确要求）

| # | 需求 | 说明 |
|---|---|---|
| R1 | **帖子 AI Summary** | 对每篇 KOL 帖子做内容摘要（1–2 句），展示在列表与详情中 |
| R2 | **帖子类型识别** | AI 判定每篇帖子的行为类型，如「甩单/晒单」等；类型候选清单见第四节，需客户确认 |
| R3 | **自家 vs 竞品发文统计** | 统计每位 KOL 的发帖中：提及自家 ETF 的篇数、提及竞品 ETF 的篇数（基于客户维护的产品池映射，规则匹配即可，不依赖 AI） |
| R4 | **官号帖子 Summary** | 官号动态页同样对每篇官号帖子输出 AI 摘要（当前页面只有账号级汇总，需新增帖子级列表） |

### 2.3 保留项（不受影响）

- 三级筛选联动（ETF → KOL → 帖子）、时间范围切换、原帖跳转链接；
- KOL 详情页「其他产品观点及操作」表——它本来就是**帖子级摘要 + 操作标签**，与新方向完全一致，将升级为该页主模块；
- 官号清单、发行商 vs 平台运营占比、发布强度 Top 8。

### 2.4 待客户确认的开放问题

| # | 问题 | 建议默认值 |
|---|---|---|
| C1 | 「甩单」的准确含义是否为"晒出实际成交单/持仓截图"？与"宣布买卖操作但无截图"是否要区分？ | 区分为「晒单」与「操作宣告」两类 |
| C2 | 类型清单（第四节 8 类）是否认可、有无需要增删？ | 按第四节执行 |
| C3 | 帖子的评论数/赞数/转发数（纯计数）是否保留展示？ | 保留，作为互动量参考 |
| C4 | Summary 输出语言（繁体中文 / 跟随原帖语言）？ | 繁体中文 |
| C5 | 提及自家/竞品的判定口径：仅看帖子挂载的标的，还是正文中出现代码/产品名也算？ | 两者取并集，并在界面注明口径 |

## 三、改版设计方案（逐页）

设计原则：删掉的空间不是留白，而是让 **AI 摘要成为版面主角**——客户现在买单的核心价值是"不用点开原帖就知道 KOL 在说什么、什么类型、帮谁说话"。

### 3.1 KOL 影响力页（kol-activity.dc.html）

页面定位从「KOL 发帖与评论区反应」改为 **「KOL 发帖内容与阵地分布」**。

**① KPI 区（4 卡重构）**

| 旧 | 新 |
|---|---|
| 发帖数 | 发帖数（涉及 X 位 KOL） |
| 评论区评论合计 | **提及自家产品** X 篇（占比 %） |
| 全站多出来的评论 | **提及竞品** Y 篇（占比 %） |
| 好评差评的变化 | 互动量合计（赞 + 评 + 转）或「操作类帖子 N 篇」 |

**② 筛选条**：保留 ①ETF → ②KOL → ③帖子 三级联动，**新增「④类型」筛选**（多选，按第四节枚举）。

**③ 发帖记录表（核心改动）**

新列设计（旧 9 列 → 新 8 列，AI 摘要为主列）：

| 合作 KOL | 发帖时间 | ETF | 类型 | AI 摘要（主列，约 40% 宽，两行截断） | 阵营 | 赞 / 评 / 转 | 原帖 |
|---|---|---|---|---|---|---|---|

- **类型**：彩色标签。操作类（晒单/操作宣告）用琥珀色系，观点类用蓝色系，推介类用绿色系，活动类用紫色系——一眼扫出"谁在甩单"。
- **阵营**：`自家`（CSOP 蓝底）/ `竞品`（银灰底）/ `双方`（分割双色），来自 R3 的标的映射。
- **AI 摘要**：正文级字号，悬停展示完整内容；这是版面上最宽的一列。

**④ 侧边抽屉重构 →「帖子内容卡」**

保留点行弹抽屉的交互与"该 KOL 区间内 N 篇"的切换胶囊，内部内容全换：

1. 头部：KOL 名、发帖时间、ETF 标签、类型标签、阵营标签；
2. **AI 摘要**（大字号引述块）；
3. **原文全文/长摘录**（浅底引用块，满足"摘要须可追溯到原文"的既有确认口径 Q13）;
4. **提及产品清单**：帖内提到的每只 ETF 代码 + 自家/竞品归属；
5. 互动计数行：赞 / 评论数 / 转发 / 浏览（注明"发布后约 24h 的值"）；
6. 底部按钮：查看 KOL 完整详情 → / 在 Futu 查看原帖 ↗。

**⑤ 排名模块 →「KOL 声量排名」**

| # | KOL | 篇数 | 自家/竞品构成（双色堆叠条：蓝=自家，灰=竞品） | 互动合计 | 主要类型 |
|---|---|---|---|---|---|

排序按篇数（或互动合计，提供切换）。原「负面 N」标记依赖评论情绪，删除。

**⑥ 洛伦兹「评论的人」模块**：整块删除。

### 3.2 KOL 详情页（kol-detail.dc.html）

**① 头卡 stats（4 格重构）**：发帖数 ｜ 提及自家 X 篇 ｜ 提及竞品 Y 篇 ｜ 互动合计。KOL 名旁新增**主要类型标签**（如「常晒单 · 偏行情解读」，由区间内类型分布自动生成）。

**② 右侧图表区**（替换"每小时评论数"图）：

- 上：**自家 vs 竞品发帖时间线**——按天的双色堆叠柱（蓝=自家、灰=竞品），直观看这位 KOL 最近帮谁发声；
- 下：**类型构成横条**——该 KOL 区间内 8 类帖子的占比分布。

**③ 左侧帖子表**：列改为 `发帖时间 ｜ ETF ｜ 类型 ｜ AI 摘要 ｜ 阵营 ｜ 赞/评/转 ｜ 原帖`，点行右侧图表高亮对应日期。

**④ 「其他产品观点及操作」表升级为主模块**：结构不变（产品/观点/操作/日期/互动量/链接 + 展开原文），它已经是"帖子级 Summary + 操作标签"的正确形态；「操作」列的取值并入第四节统一的类型枚举，保留 CSV 导出。

### 3.3 官号动态页（official-activity.dc.html）

现状只有账号级汇总，**新增帖子级内容流**（客户本次核心诉求 R4）：

- 版面从「左清单 + 右两卡」改为**上下两段**：上段保留官号清单 + 占比卡 + Top8（压缩高度）；
- 下段新增 **「官号发帖流」**：时间倒序卡片列表，每卡包含——官号名 + 类型标签（发行商官号/平台运营）+ 发布时间 + **AI Summary（主体）** + 提及产品标签（自家蓝/竞品灰）+ 赞/评/转 + 原帖链接；
- 顶部提供官号筛选（沿用清单的 全部/发行商官号/平台运营 三态）与产品筛选；
- KPI 第 4 卡改为「已生成摘要 N 篇」。

## 四、AI 能力规格（新增，供开发与客户确认）

**输入**：帖子标题 + 正文（图片内容第一期不承诺）。
**输出**（每篇帖子）：

```json
{
  "summary": "≤60 字摘要，繁体中文",
  "post_type": "枚举，见下表",
  "type_evidence": "判定依据的原文句子（可追溯）",
  "mentioned_tickers": ["03033", "07226"],
  "camp": "own | competitor | both | none"
}
```

**帖子类型枚举（8 类，待客户确认 C1/C2）**：

| 类型 | 定义 | 判定线索举例 |
|---|---|---|
| 晒单（甩单） | 贴出实际成交记录 / 持仓截图 | "今日成交""已建仓" + 截图类措辞 |
| 操作宣告 | 宣布买入/卖出/调仓意向，无凭证 | "准备加仓""清仓离场" |
| 行情解读 | 对市场或标的走势的分析观点 | 技术面/资金面/宏观叙述 |
| 产品推介 | 介绍或安利某只 ETF 的特点 | 费率、杠杆倍数、跟踪指数介绍 |
| 教学科普 | 知识型内容，不针对特定操作 | "什么是备兑策略" |
| 活动/福利 | 转发平台或发行商活动、抽奖 | 活动链接、抽奖规则 |
| 问答/互动 | 向粉丝提问、征集观点、回应评论 | 问句结尾、投票 |
| 其他 | 无法归入以上 | — |

**规则**：低置信度（<0.7）标注「待确认」灰标；`camp` 由 mentioned_tickers 对照客户维护的产品池（61 自家 + 59 竞品）映射得出，不走模型；摘要随采集批次更新（对齐既有的 60 分钟汇总口径）。

## 五、实施拆解与验收

**改动文件清单**：

| 文件 | 改动 |
|---|---|
| `radar-data.js` | posts 数据结构新增 `summary` / `postType` / `typeEvidence` / `mentioned` / `camp` 字段；官号新增帖子级 mock 数据；删除 series（每小时评论）、好差评、洛伦兹相关生成逻辑 |
| `kol-activity.dc.html` | 按 3.1 重构：KPI、表列、抽屉、排名、删洛伦兹模块、新增类型筛选 |
| `kol-detail.dc.html` | 按 3.2 重构：stats、双图、表列，升级观点操作表 |
| `official-activity.dc.html` | 按 3.3 新增官号发帖流 |

**验收标准**：

1. 全站不再出现任何"好差评 / 每小时评论 / 评论摘录 / 评论人"字样与图表；
2. 每篇 KOL / 官号帖子均有摘要、类型、阵营三项标注，且摘要可展开查看原文依据；
3. 任一 KOL 可在 3 秒内回答三个问题：他最近发了什么（摘要）？什么行为（类型）？帮谁说话（自家/竞品篇数）；
4. 类型枚举与「甩单」定义经客户书面确认后冻结。
