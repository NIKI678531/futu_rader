# ADR-0040 — 分域自选日期、账号快读与页面评论时钟

- **状态**：已接受
- **日期**：2026-10-30
- **补充**：[ADR-0039](0039-custom-date-fact-first-no-on-demand-synthesis.md)

## 决策

1. 市场域（板块总览、产品监控）自选日期最多 31 个含首尾自然日；账号域（官号动态、KOL 影响力及 KOL 详情）最多 1 个自然年。1 个自然年使用同月同日前一日为含首尾上限，因此跨闰日可为 366 天。
2. 前端从 `/meta.customRange.scopes` 读取能力，服务端仍按端点所属域再次校验。跨域导航恢复目标域上次合法区间；没有记录或当前区间对目标域无效时使用默认 D7，不静默裁剪日期。
3. 账号页面不因自选日期触发 AI 任务，只读取现有帖子事实和已发布标注。KOL 表与详情首屏最多渲染 50 篇，长于 31 天的详情时间线使用后端自然周桶；SQL 使用作者—发布时间复合索引，进程启动后预热默认 D7 账号页。
4. 公共页头同时显示「评论截至」与「页面更新」。前者是当前页面数据范围内已入库评论的最大真实 `comments.posted_at`；后者是 `ai_public_updated_at`。评论时间部分缺失时显示「已抓取评论最新」和覆盖数，全部缺失时显示「暂不可用」，不得以父帖时间、同步时间或系统时间替代。
5. 页面日期范围仍按父帖发布时间选择。因此评论真实发帖时间可以晚于所选父帖区间；页面提示说明该时间属于所选帖子下的评论。

## 后果

- 账号历史分析覆盖显著扩大，而市场聚合与行情查询仍保持短窗成本上界。
- 历史评论时间不完整会以部分覆盖显式出现，不再把刷新时间误读为评论数据截止。
- 新增复合索引需要随 Alembic `0019` 部署；旧前端仍可读取兼容的 `/meta.customRange.maxDays=31`。
