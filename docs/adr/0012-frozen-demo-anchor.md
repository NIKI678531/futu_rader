# ADR-0012 — 演示期时间锚点冻结

- **状态**：已接受，**2026-09-10 补充：两个 provider 各有各的锚点**（见文末）
- **日期**：2026-09-09
- **相关**：[ADR-0006](0006-dual-acceptance-criteria.md)、[ADR-0008](0008-dump-import-and-slim-db.md)

## 背景

`design/radar-data.js` 把「现在」写死了：

```js
var ANCHOR   = '2026-09-01';   // 最近一个完整自然日（HKT）
var NOW_DATE = '2026-09-02';
var NOW_TIME = '09:00';
```

后端供数后，`updatedAt` 和区间要么继续冻结在这里，要么跟随真实今天浮动。

## 决策

**演示期冻结。** `anchorDate` / `updatedAt` 由 `GET /meta` 下发，前端**一个字都不自己算**（PRD §5：「后端下发，前端不自行算桶」）。

真实通道成熟后，改的是后端一个常量。

## 理由

冻结才有可比基准。一旦浮动，`npm run design` 的并排比对当场对不上——而那正是 [ADR-0006](0006-dual-acceptance-criteria.md) 定的 `demo` provider 验收方式。截图、录屏、回归基线同理。

## 后果

- `mysql` provider 的区间也按同一锚点取（即「最近 30 天」＝ 2026-08-03 ~ 2026-09-01），否则两个 provider 的区间对不齐，无法并排比对。
- 演示材料上的「更新于 2026-09-02 09:00 HKT」是**固定文案**，不要被误认为系统卡住了。
- 锚点是**唯一**的时间真源。前端出现 `new Date()` 参与业务计算即为违规。

## 否决的备选

- **跟随真实今天**：验收基准消失。
- **可配置但默认浮动**：默认值决定了绝大多数人看到的行为，等同于上一条。

---

## 补充（2026-09-10）：真实数据接上后，两个 provider 的锚点不同

上面「后果」第 1 条要求 `mysql`（现 `sql`，见 [ADR-0016](0016-sqlite-local-mysql-prod.md)）provider 用同一个锚点 2026-09-01。真实数据接上后**这一条不成立**：dump 里的数据止于 **2026-08-26 03:00**，2026-09-01 那一天一条帖子都没有。

**修正为：锚点仍是唯一的时间真源、仍由 `/meta` 下发、前端仍一个字都不自己算——但它的值由 provider 各自决定。**

| provider | 锚点 | 来源 |
|---|---|---|
| `demo` | `2026-09-01` | 设计源常量，冻结不动 |
| `sql` | `2026-08-25` | 导入时实测写进 `meta_kv.anchor` |

两个都满足「最近一个完整自然日（HKT）」这个**定义**——变的是数据，不是口径。

### 为什么是 08-25 而不是 08-26

dump 打包于 2026-08-26 11:01，所以那天只有 03:00 前的 657 篇帖子，而正常日均约 5,000 篇。拿 08-26 当锚点，「昨日」会显示成 87% 的断崖式下滑——一个纯粹由采集时点造成的假信号，且它在界面上和真的舆情塌方长得一模一样。

`worker/jobs/import_dump.py` 的 `anchor_of()` 因此定为：**取最大 `posted_at` 那天；若那天没跑到 23 点，退一天**。数据实际到哪一刻单独记在 `meta_kv.data_max_ts`（`2026-08-26 03:00:09`），没有被丢掉。

### 对 [ADR-0006](0006-dual-acceptance-criteria.md) 并排比对的影响

`demo` provider 的锚点没动，所以 `npm run design` 的逐像素比对基准**完全不受影响**。`sql` provider 本来就不参与那项验收——它的验收标准是另一条（真实数字对得上库里的 SQL）。

### 仍然成立的部分

- 锚点是唯一的时间真源；前端出现 `new Date()` 参与业务计算即为违规。
- **拿不到锚点时返回 `null`，不用系统时间兜底**（`core/calendar.parse_anchor`）。今天是 2026-09-10，按系统时间算「近 7 天」会得到一个空窗口——在界面上和「这周确实没人发帖」无法区分。
