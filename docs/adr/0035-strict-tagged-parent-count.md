# ADR-0035 — 筛后评论量按严格 tag 父帖一帖一条

- **状态**：已接受
- **日期**：2026-10-17
- **取代**：[ADR-0029](0029-parent-feed-comment-qualification.md) 中产品级
  `comments = SUM(feeds.comment_count)`，以及标题与正文拼接后解析 cashtag 的做法

## 背景

业务核对 2026-10-16 12:00 HKT 前数据时，3537、2802、7226 的实际合格内容分别是
4、2、23 篇。旧实现虽然先筛出了带自身 ETF tag 的父帖，却随后累加这些父帖的
`comment_count`（平台回复数），页面因此显示 9、6、5。零回复的合格帖子对主数贡献为零，
多回复的单篇帖子又被重复计数。

另有一篇 7226 帖子标题以金额符号 `$` 结尾、正文为 `$07226.HK$`。把标题与正文拼成
一个解析流会让标题末尾 `$` 吃掉正文 cashtag 的起始 `$`，导致有效内容被误排除。

## 决策

1. `title` 与 `content` 分别解析严格 cashtag，再按 ticker 合并及累计出现次数；不得跨字段
   配对美元符号。
2. 产品级 `comments`、排名、趋势、环比及热度中的评论分量均为合格父帖数，每篇只计 1。
3. `feeds.comment_count` 继续作为平台回复计数保留在采集元数据和评论漏斗；它不再进入产品
   主指标。`comments` 表行数继续表示 AI 实际取得的回复正文数。
4. 父帖资格仍由原讨论区 `feeds.code`、`source_ticker` 与自身严格 cashtag 共同限定；回复不
   能救回父帖或改变产品归属。
5. 解析规则升级为 `parent-feed-v3` / `content-cashtag-v2`，上线时必须回填
   `feed_mentions` 和评论路由，readiness 未激活期间产品筛选指标保持不可用。

## 后果

- 一篇合格内容无论收到多少回复都只计 1；无回复但带自身 tag 的内容不再消失。
- 平台回复覆盖与页面筛后评论量单位不同，接口继续分别披露，不能直接相减或互换。
- 历史排名、趋势、环比与热度会按新口径整体重算。
