# ADR-0011 — 「评论量」与「态度样本」用两个不同来源

- **状态**：已接受（含一条**待客户确认**）
- **日期**：2026-09-09
- **相关**：[ADR-0008](0008-dump-import-and-slim-db.md)、[ADR-0009](0009-worker-scope.md)

## 背景

PRD §3.3 定义「评论量 ＝ 被识别为讨论该产品的**评论条数**」。

数据侧的实情：

- MySQL 列里**没有评论表**，只有帖子级 `comment_count` 计数器。
- 但 `raw_json.comment.comment_items` 里**有评论正文**（`rich_text_items[].text`，部分行还有扁平化的 `content`），带作者、时间、获赞、`reply_to_comment_id`。
- 富途接口**分页返回评论**。全库统计：

  ```
  has_more = 0   956,105   (96.5%)
  has_more = 1    34,941   ( 3.5%)
  ```

  96.5% 的帖子评论是全量嵌入的；被截断的 3.5% 几乎必然是评论最多的热帖，**占评论总量的份额会远高于 3.5%**。

## 决策

**两个来源各司其职：**

| 用途 | 来源 | 理由 |
|---|---|---|
| 「评论量」这个**数字**、热度公式 | 帖子级 `comment_count` | 平台计数器，不受截断影响，与 `COUNT_NOTE`（「取发布后约 24 小时的值」）自洽 |
| **态度／主题／摘录** | 解析出的评论表 | 96.5% 的帖子全量可用；不足的按 PRD §3.5 走「样本不足」 |

两者的差异是**可陈述的**（「热度基于平台计数；态度基于已采集到的 N 条评论，占比 M%」），不是隐藏的近似——这正是六态存在的意义。

## 待客户确认

**「评论量 ＝ Σ 帖子 `comment_count`」与 PRD §3.3 原文「被识别为讨论该产品的评论条数」有真实偏差**：帖子挂在某只标的的讨论区，其下 N 条评论未必逐条在讨论该产品；PRD §3.2 的「提及去重」在这个数据形状下也无法逐条执行。

这不是工程能替客户拍板的口径变更。**代码按本 ADR 实现，第一期演示时报备。**

同时报备第二条：**被上游截断的 3.5% 热帖，导致态度分析基于子集**。精确影响由 [ADR-0008](0008-dump-import-and-slim-db.md) 的导入后验证 1 给出。

## 后果

- 同一个页面上，「评论量」和「态度样本数」会是两个不同的数。**必须在界面上说清楚**，否则会被读成 bug。
- `M%`（态度样本覆盖率）应当作为一个可展示的字段，而不是藏在文档里。

## 否决的备选

- **只用 `comment_count`**：拿不到逐条评论，态度、主题、摘录整个模块塌掉——那是五个页面里最有价值的部分。
- **只用解析出的评论**：首页数字会因截断而系统性缩水，且缩水幅度不可解释。
