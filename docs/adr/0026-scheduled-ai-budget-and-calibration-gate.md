# ADR-0026 — 自动 AI 以完整日期为门槛，并使用持久日预算与校准闸门

- **状态**：已接受
- **日期**：2026-09-25
- **取代／限定**：本 ADR 仅对生产定时链路取代 [ADR-0021](0021-student-funnel.md) §5
  与「后果」中的 LLM 并发 16–24，以及并发 24 时历史积压 ≤30 分钟、低于 24 时退为
  40 分钟的容量假设。日常自动链路固定 batch size 5、并发 2，并受每个实际 HKT 自然日
  500 次 HTTP 尝试硬上限约束；30／40 分钟不再是其 SLA 或验收项。ADR-0021 的
  Student → Luna 漏斗、批 5 一致性闸门和逐区间 dirty 语义保留。历史 backfill 若重新
  启用，必须使用显式任务、独立容量／预算决策和新 ADR，不得靠调高日常 DAG 并发实现。
- **保留**：[ADR-0017](0017-ai-annotation-pipeline-production.md) 与
  [ADR-0019](0019-ai-auto-publish-no-human-gate.md) 的数据治理前置条件；部署定时 DAG
  不等于批准把评论发送给外部模型。
- **相关**：[ADR-0017](0017-ai-annotation-pipeline-production.md)、[ADR-0019](0019-ai-auto-publish-no-human-gate.md)、[ADR-0021](0021-student-funnel.md)、[ADR-0024](0024-airflow-source-boundary-and-dataset-sync.md)

## 背景

自动同步接通后，事实可以一天多次变化，但 AI 不应在每次采集后无限调用。Airflow 重试、
模型内部重试和跨午夜运行还会让单纯的“每个 DAG run 最多 N 次”失效。另一方面，批量
请求虽然省调用数，却只有在同一模型、Prompt 和请求边界上通过校准后才有资格自动运行。

ADR-0019 已裁定模型结果自动发布，ADR-0021 已裁定 Student → Luna 的漏斗；本 ADR 只规定
生产自动运行何时可以开始、最多发多少次 HTTP，以及不满足条件时如何安全停下。

## 决策

### 1. 只在完整同步后启动当日分析

Airflow 在香港工作日 20:30 启动 AI 编排。任务先等待当日 19:30 `comments_all` 的成功回执，
以及 Radar 对该精确 source run 的成功同步；最长等待 8 小时，超时失败且不猜完整日期。

周二至周五运行 `d1,d2`；周一运行 `d1,d2,d7,d14,d30,mtd`。计划日用于选择分析范围，
不用于制造新的预算桶。

### 2. 每次真实 HTTP 尝试前原子扣减香港自然日预算

每个实际香港自然日硬上限 500 次 HTTP 尝试，默认 batch size 5、并发 2。初次请求和
provider 内部重试都必须先在 `ai_daily_budget` 原子预留一次；拿不到额度就不发送请求。

预算以**发出请求的实际香港日期**计费，不信任调用方传入的计划日。Airflow 重试、任务
重启和跨午夜不会清零已用额度；同一天也不允许静默更换模型／Prompt／schema／taxonomy／
batch／并发组合后继续共用旧策略。

这组参数取代 ADR-0021 为历史积压提出的生产并发与时长目标。并发是容量／限流参数，
不是本校准报告的准确性维度。未来提高并发必须先重新做网关并发探测、评估日预算与运行
窗口并另写 ADR；若同时改变模型、Prompt、schema、taxonomy、batch size 或任一请求边界，
还必须生成精确匹配的新校准报告。

### 3. 校准不匹配时零调用

自动批量 AI 必须提供已通过的校准报告。报告必须与当前模型、Prompt、schema、taxonomy、
batch size、最大输入 token、最大载荷字节和最大输出 token 完全一致，并明确记录
`batchGatePassed=true`。缺失、无效或策略不匹配时，在创建第一个付费请求前失败。

生产环境可通过 Secret 注入完整 JSON，也可挂载只读报告文件；两种形式执行同一校验。
这里的校准是**请求前的批处理一致性闸门**：它证明当前模型／Prompt／schema／taxonomy／
batch 与请求边界和报告一致，且 b=1 对 b=5 的实验达到既定阈值。它不是 ADR-0017 的
逐条 `calibrated_confidence`，不证明结论与人工真值一致，不改变 `/meta.aiValidation`，
也不替代数据治理批准。只有 ADR-0021 §6 的独立人工金标评估可以把 `aiValidation` 从
`none` 改为 `spot_check`；该评估仍只是量尺，不是发布批准。

### 4. 数据治理批准与结果发布是两道不同的门

部署或调度定时 DAG 不构成持续向外部模型发送评论的授权。
[ADR-0020](0020-llm-only-90d-pilot.md) §8 的 2026-09-14 授权只覆盖该次 90 天试点，
不自动延伸为长期生产调度。自动任务在任何校准或 HTTP 尝试
之前，还必须收到 Secret 中显式的
`AI_DATA_GOVERNANCE_APPROVED=true`。设置它表示运行方已经完成 ADR-0017/0019 所列的
处理地区、日志保留、训练使用和删除机制确认；仓库不保存该批准，也不能替组织代签。
缺失或为 false 时，定时 DAG 可以被调度，但必须零调用失败。

这是**发送数据前的部署授权门**，不是结果发布门，也不是人工准确率门。获准且模型成功
生成后，结论仍按 ADR-0019 自动成为现行结论：非 `rejected` 的链末行立即可读，
`pending` 与 `needs_review` 都不等待人工批准。

### 5. AI 失败不回滚事实

同步成功后事实立即可读。预算耗尽、网关错误或某个产品／区间失败，只保留其
pending/stale 状态；不回滚 feeds、comments、mentions、users，也不谎报为完成。

`AiResult` 的 `completed_ranges` / `pending_ranges` 从每个 `(product, range)` 的持久
`synth_dirty` 状态计算，因而重试可以接着做，部分成功也不会被进程内状态抹掉。

## 理由

- 完整 source run 与目标同步双重门槛，避免用半天数据生成“每日”结论。
- 数据库原子预算覆盖 Airflow 并发、provider 重试和进程重启；内存计数做不到。
- 校准报告绑定完整策略，防止换模型或调大 batch 后沿用旧结论放量。
- 显式治理批准把“任务已经部署”和“允许把真实评论发出去”分开，保留旧 ADR 的安全边界。
- 事实与推理分离后，AI 服务故障不会阻断基础数据发布。

## 后果

- 自动 AI task 在 Airflow 层不重试；若以后启用重试，持久预算仍是唯一上限。
- 生产 Secret 未明确提供治理批准时，自动任务保持零调用；运维不能把“有 API key”当授权。
- 每次 AI 策略变更都需要生成与新策略精确匹配的校准报告。
- “完成”按产品与区间判断，不能再以一个进程正常退出代替完成证明。

## 否决的备选

- **每个 DAG run 各给 500 次**：任务重试即可绕过日上限。
- **请求返回后再计数**：并发时会超额，超时请求也会被漏记。
- **采集一完成就立即跑 AI**：一天内重复重算，且可能早于全量晚场采集。
- **AI 失败回滚同步**：把外部模型可用性错误地变成事实数据不可用。
