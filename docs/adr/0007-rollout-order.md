# ADR-0007 — 接入顺序：账号域先行

- **状态**：已接受
- **日期**：2026-09-09

## 背景

五个屏对契约函数的依赖量差了一个数量级：

| 屏 | 依赖的契约函数 | 数量 |
|---|---|---|
| 官号动态 | `officialPosts` `etfMentionsFor` | **2** |
| KOL 影响力 | `kolImpact` `kolProfile` | **2** |
| KOL 详情 | `kolImpact` `kolProfile` `kolOpinions` | **3** |
| 板块总览 | `observe` `pool` `ranks` `benchmark` `summaryFor` `hotSummaryFor` `themesFor` `negCatsFor` `competitorsFor` `complianceFor` | **10** |
| 产品监控 | 上列 10 个中的 8 个 ＋ `topicsFor` `evidenceFor` `kolMentionsFor` `candlesFor` `stagesFor` | **13** |

账号域 3 个屏总共只压着 **5 个端点**（去重后）。

## 决策

**官号动态 → KOL 影响力 → KOL 详情 → 板块总览 → 产品监控**

## 理由

1. **最小面积先跑通基础设施**。垫片、缓存、六态、两套验收这一整套机制先在 5 个端点上验证，出问题时排查范围小。
2. **账号域的字段在真实数据里存在**——帖子、作者、粉丝数、正文里的 ETF 提及，全部直接可得。`mysql` provider 从第一个屏就有真东西看，不会一上来满屏「暂不可用」，能尽早判断真实通道值不值得继续推。
3. **产品监控放最后**：13 个契约、1793 行源码，此时基础设施已被三个屏磨过。
4. 附带好处：`/` 本来就重定向到 `/official`，第一个做完的屏就是落地页。

## 后果

- 客户最关心的产品监控最晚可见。演示节奏上要提前说明，否则会被读成「进度慢」。
- 板块总览与产品监控共享 8 个契约，第 4 个屏做完时第 5 个屏已经完成大半。

## 否决的备选

- **客户价值优先（产品监控先做）**：把最大的屏和最不成熟的基础设施撞在一起，最可能的结果是两边同时返工。
- **按导航顺序（市场域先行）**：与理由 1、2 全部相反。
