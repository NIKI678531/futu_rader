# ADR-0005 — 同步垫片，以及「100% 还原」的定义

- **状态**：已接受
- **日期**：2026-09-09
- **相关**：[ADR-0004](0004-radar-member-split.md)、[ADR-0006](0006-dual-acceptance-criteria.md)

## 背景

产品要求五个页面与 `design/*.dc.html` **100% 还原**。

而 [README.md](../../README.md) 记录的移植教条是：`state`、生命周期、`renderVals()` **逐字**拷自设计源，设计变更时**重新拷贝而不是照着手推**。`product-monitor` 有 1793 行、`sector-overview` 1295 行，这条逐字可比性是它们唯一可维护的方式。

把屏改成 async / hooks 会一次性烧掉这个属性。

## 决策

### 1. 同步垫片，不做 async 化

路由层在渲染屏之前 `await loadScreen(name, params)`，把结果填进 `RadarStore`；屏内所有 `R.xxx()` **保持同步签名**，从 store 同步读，未命中返回 `na` 而不是抛异常。

屏代码几乎零改动。代价是 **屏级 loading**（一屏一个 spinner，不做块级骨架屏）——对只读工作台可接受。

### 2. 「100% 还原」＝ 可见输出等价，不是源码等价

判定标准：**同一 URL 参数下，移植版与设计源渲染出的可见文本与数值完全一致**。

[README.md](../../README.md) 记录的四条有意偏差**明示豁免**，不要求撤销：

| 偏差 | 为什么不影响可见输出 |
|---|---|
| 去掉 `window.RADAR` 轮询 | 加载时序，不改变最终渲染 |
| `history.replaceState` 改写 URL | 地址栏行为，与设计源一致 |
| 删掉模板不读的死值 | 模板根本不读 |
| 给列表补 React `key` | JSX 语法要求，不产生可见节点 |

### 3. 垫片不补任何默认值

垫片**原样透传**后端的 `data`，形状与镜像函数返回值逐字一致。六态通过**字段级 `null`** ＋ 既有 `status` 字段表达（`candlesFor` / `complianceFor` 本来就带 `status`，不是新发明）。

垫片里出现 `?? 0`、`|| 0`、`|| []` 一律视为铁律 2 的违反，加 lint 规则拦。

### 4. 两类失败分开

- **网络错误 / 5xx** → 屏级错误条（「加载失败，请重试」）
- **数据不可用** → 字段级「暂不可用」

混在一起，前端就分不清「后端挂了」和「这个产品没这个数」。

## 后果

- 屏级 loading 意味着慢端点会拖住整屏。缓解：[ADR-0003](0003-endpoint-granularity.md) 的 1:1 端点是并发拉的，屏的等待时间是**最慢的那个**，不是总和。
- `RadarStore` 成为一个新的关键组件，它是唯一有资格「知道数据从哪来」的地方。

## 否决的备选

- **逐屏 async / hooks 改造**：块级骨架屏更好看，但要重写 3000+ 行 `renderVals()`，与设计源的 diff 关系当场断掉，设计再变更时无法重拷。这是拿最贵的资产换一个次要的体验改进。
